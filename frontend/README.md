# Т-Страхование · клиентское приложение и кабинет оператора

Клиентские экраны и кабинет оператора на Kotlin и Compose Multiplatform для Android, iOS и Web.
Общая вёрстка находится в `shared/src/commonMain`, платформенные точки входа используют один `App`.

[Макет в Figma](https://www.figma.com/design/s6nhRji3xk5E3It2m9SskY/)

## Запуск

Нужен JDK 21. Для Android установите SDK 37, для iOS — Xcode на macOS.
Команды выполняются из папки `frontend` (в Windows используйте `gradlew.bat`).

```bash
./gradlew :androidApp:assembleDebug
./gradlew :webApp:wasmJsBrowserDevelopmentRun
# Другой вариант Web:
./gradlew :webApp:jsBrowserDevelopmentRun
```

Для iOS откройте `iosApp/iosApp.xcodeproj` в Xcode.

### Backend

Приложение ходит в `/api/mobile` на `http://localhost:8080` (из эмулятора Android — `10.0.2.2:8080`),
Web-версия работает на `localhost:3000` — этот адрес разрешён в CORS backend.
Модели API (`ru.tinsurance.api`) подключены из `../backend/core` через `includeBuild`, поэтому папка `backend`
должна лежать рядом.

Запускайте backend не через Gradle: `./gradlew :server:run` держит блокировку сборки `backend/`,
и Gradle фронтенда ждёт её. Удобнее контейнер (из папки `backend`):

```bash
./gradlew :server:buildFatJar
docker compose --profile app up -d --build
```

В dev-режиме сервер создаёт демо-учётки: клиенты `+79000000001…03`, пароль — `DEV_DEMO_PASSWORD`
в `backend/server/src/main/kotlin/ru/tinsurance/server/demo/DemoData.kt`.

### Кабинет оператора · экраны 13–18

Откройте `http://localhost:3000/#OperatorQueue` или нажмите «Демокабинет оператора» на экране входа.
В профиле оператора есть переход обратно к клиентскому приложению.

| № | Экран | Ссылка в Web |
|---|---|---|
| 13 | Очередь обращений | `#OperatorQueue` |

| 15 | Материалы и анализ фотографии | `#OperatorMaterials` |
| 16 | Ручное исправление | `#OperatorCorrection` |
| 17 | Запрос дополнительных материалов | `#OperatorRequest` |
| 18 | История изменений | `#OperatorHistory` |

Это локальный демонстрационный сценарий вёрстки: запросы и исправления не отправляются в backend,
письма и уведомления клиентам не отправляются. Изменения сбрасываются при выходе из кабинета или перезапуске приложения.
Кабинет не обходит авторизацию операторского API и не предоставляет доступ к реальным обращениям.

Работают поиск по номеру обращения и полиса, комбинированные фильтры, вкладки, десять страниц очереди,
взятие обращения в работу, выбор вложения, увеличение и скачивание фото, скачивание учебного PDF,
исправление с обязательной причиной, запрос выбранных материалов, завершение обработки и журнал событий.
Чужое обращение доступно только для просмотра. Счётчики пересчитываются после действий.
Журнал хранит предыдущие исправления отдельно для каждого обращения и фотографии.

Все шесть экранов находятся в `shared/src/commonMain/kotlin/com/tinsurance/app/operator`.
`OperatorPreviews.kt` содержит отдельные `@Preview` 1440 × 900. На узких экранах рабочая область
прокручивается по горизонтали; содержимое и длинные формы прокручиваются по вертикали.
Иконки, фотография и область повреждения взяты из Figma, исходные SVG сохранены в
[`docs/operator-assets`](docs/operator-assets). Шрифт и общие компоненты используются из клиентской части.

На экране входа есть ссылки в кабинет администратора и к выбору роли. В профилях можно вернуться к выбору роли. Клиентский демосценарий открывается с учебными обращениями; обычный вход клиента продолжает использовать API.

В кабинете работают поиск и фильтр очереди, выбор обращений, выбор исполнителя, переназначение с обязательной причиной, проверка доступности и свободных мест, сохранение текущего приоритета или выбор нового. После назначения обновляются очередь, загрузка сотрудников и журнал с автором и причиной.

Правила позволяют выбирать обязательные материалы, порог уверенности, маршруты и сроки. Вкладки показывают соответствующие группы настроек; «Отмена» возвращает сохранённые значения. Порог проверяется в пределах 0–100%, сроки — в целых положительных часах. Сохранённые изменения видны в журнале.

Кабинет использует локальные демонстрационные данные. Его изменения сохраняются при переходах между разделами и сбрасываются после выхода из кабинета или перезапуска. Серверные настройки и реальные назначения остаются в административном API.

Вёрстка использует `InsuranceTheme`, `InsuranceCard`, `InsuranceButton`, общие поля и существующие компоненты оператора. `AdminPreviews.kt` содержит превью 1440 × 900 для всех четырёх экранов. На узком экране рабочая область прокручивается по горизонтали, длинные разделы — по вертикали.

## Как устроен код

- `App.kt` — переходы между экранами и локальное состояние сценария.
- `data/` — `MobileApiClient` (Ktor, JWT с автообновлением) и адрес backend для каждой платформы.
- `client/ClientViewModel.kt` — вход, выход и список обращений из API.
- `client/` — обычные Compose-функции экранов, черновик и проверка полей.
- `operator/` — шесть экранов оператора, общая оболочка и локальное состояние демонстрации.
- `admin/` — обзор, команда, правила, очередь, журнал и состояние демонстрационного кабинета.
- `demo/` — выбор роли и переход в нужный кабинет.
- `ui/` — тема, кнопки, поля, карточки, шапка и нижнее меню.
- `PlatformFiles.*.kt` — камера, сохранение PDF и системная кнопка «Назад».
- `composeResources/` — изображения и иконки из Figma, шрифт Inter и два учебных PDF.

Поля, вкладки, выбор договора, чекбоксы, просмотр обращений и уведомления работают.
Черновик хранится через `rememberSaveable`: введённые значения не теряются при переходах между экранами.
На узком экране содержимое прокручивается, нижняя кнопка остаётся доступной; учитываются системные отступы и клавиатура.

FileKit открывает системный выбор файлов на всех платформах. Камера работает на Android/iOS;
в браузере эта кнопка открывает выбор изображения. Принимаются JPEG, PNG и PDF: до 20 МБ на файл,
10 файлов и 100 МБ на обращение. Повторно выбранные файлы сравниваются по содержимому.

## Тестовые данные

Вход, профиль, полис, список «Мои обращения», «Ход обработки», «Обработка завершена»,
«Центр уведомлений» (со счётчиком непрочитанных), «Запрос материалов» и «Ответ на запрос» работают с backend.
В ответе на запрос файлы сразу загружаются на сервер; качество фото сервер проверяет в фоне,
и экран показывает итог («Принят» / «Не принят» с подсказкой) через несколько секунд.
Новое обращение целиком работает с backend: шаги 1–3 («Договор и тип события», «Обстоятельства»,
«Фото и документы») создают и заполняют черновик; поля шага 2 и нужные документы берутся из правил
типа события (`GET /event-types`); черновик из вкладки «Черновики» открывается для продолжения.
Если сервер отклонил фото, перед проверкой открывается «Проверка качества фото» с его подсказкой.
«Проверка перед отправкой» показывает сводку и результат `GET /claims/{id}/completeness`: без
основных полей отправить нельзя, а без части документов можно — сервер примет обращение и сразу
запросит недостающее, что видно на экране «Обращение отправлено».
Время с сервера показывается в часовом поясе устройства.
Уведомления появляются при смене статуса обращения — например, когда оператор запрашивает материалы
или завершает рассмотрение (см. `backend/docs/NOTIFICATIONS.md`). Вход сохраняется между запусками:
refresh-токен и id установки лежат в `SessionStorage` (Web — `localStorage`, Android — `SharedPreferences`
приложения, iOS — `NSUserDefaults`), access-токен — только в памяти. При запуске приложение входит
по сохранённому токену; «Выйти» в профиле его удаляет. Остальные экраны пока работают по локальному демонстрационному
сценарию: отправка заявления и дополнения меняет состояние интерфейса, но не отправляет запросы в backend. Статусы и предупреждение о тёмном фото взяты из макета;
новые фото не проходят ML-проверку. Вкладки «Полисы» и «Профиль» открывают диалоги, поскольку отдельных
клиентских экранов для них в макете нет.

Вложения с устройства хранятся в памяти текущего запуска. После перезапуска их нужно выбрать заново.
Скачиваемые PDF — помеченные учебные образцы, а не документы, сформированные сервером.
Inter распространяется по SIL Open Font License; текст лицензии находится в `composeResources/files/inter_OFL.txt`.

## Проверка

```bash
./gradlew :shared:compileKotlinJs :shared:compileKotlinWasmJs
./gradlew :shared:jsBrowserTest
./gradlew :androidApp:assembleDebug
```

Для браузерных тестов нужен Chrome/Chromium. `ClaimValidationTest` проверяет календарные даты,
обязательные поля, адрес почты и ограничения вложений.
`OperatorStateTest` проверяет фильтры очереди, защиту чужих и завершённых обращений, обязательные поля,
назначение исполнителя и сохранение исправлений в истории.

`AdminStateTest` проверяет атомарность переназначения, лимиты исполнителей, сохранение приоритетов, причину и автора в журнале, проверку правил и разбор сроков.
