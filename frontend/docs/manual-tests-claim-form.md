# Ручные тесты: новое обращение, шаги 1–3 (экраны 02–04)

Проверяем «Договор и тип события», «Обстоятельства», «Фото и документы» и продолжение черновика.
Шаги 4–6 (проверка качества, проверка перед отправкой, отправка) пока работают по макету — в эти тесты не входят.

## Подготовка

Нужны Docker Desktop, JDK 21 и Chrome. Команды — PowerShell.

1. База (на 5432 может быть занят локальный PostgreSQL, поэтому порт 55432):
   ```powershell
   docker run -d --rm --name tins-dev-pg -e POSTGRES_DB=tstrah -e POSTGRES_USER=tstrah -e POSTGRES_PASSWORD=tstrah -p 127.0.0.1:55432:5432 postgres:16-alpine
   ```
2. Backend (первое окно, папка `backend`):
   ```powershell
   .\gradlew.bat :server:buildFatJar
   $env:APP_MODE = "dev"; $env:DB_URL = "jdbc:postgresql://localhost:55432/tstrah"; java -jar server\build\libs\server-all.jar
   ```
   Готово, когда http://localhost:8080/health отвечает `{"status":"UP",...}`.
3. Приложение (второе окно, папка `frontend`):
   ```powershell
   .\gradlew.bat :webApp:wasmJsBrowserDevelopmentRun
   ```
   Открыть http://localhost:3000.

**Файлы для загрузки** — подготовить заранее:

- 1 тёмное или маленькое фото (например, скриншот 300×200) — сервер его отклонит;
- 1 PDF (любой настоящий PDF-документ);
- 1 файл больше 20 МБ.

## F. Время в поясе устройства (регрессия)

Раньше время с сервера показывалось по UTC. Проверить на компьютере/телефоне не в UTC (например, UTC+7).

| № | Действие | Ожидаемый результат |
|---|---|---|
| F1 | D3 — повторное открытие черновика | Время то же, что вводили (14:20), а не сдвинутое на пояс (07:20) |
| F2 | Олег → обращение «на рассмотрении» → «Ход обработки» | Время шагов истории — местное |
| F3 | «Уведомления» | Время карточек — местное, группы дней по местной дате |

## Известные ограничения (не баги этих тестов)

- «Проверить материалы» на шаге 3 ведёт на экран проверки **из макета** — он будет подключён следующим.
- Нет отдельного выбора количества участников и «есть пострадавшие» — в API таких полей нет, вместо этого
  второй водитель по имени.
- Имя файла с кириллицей сохраняется на сервере с заменой букв на `_` (ограничение заголовка multipart).
- Токены в памяти: после перезапуска приложения нужно войти снова.
