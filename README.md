# 🚗 Т-Страхование: сопровождение страхового случая

**Учебный программный комплекс для приёма, первичной проверки и маршрутизации обращений по страховым событиям**

</div>

## 📖 О проекте

Система обеспечивает **полный жизненный цикл обращения**: от подачи клиентом до фиксации итогового решения оператором.

- Принимает обращение и проверяет **комплектность** и **формат файлов** до основной обработки.
- Анализирует фото повреждений с помощью **ML** (качество снимка + тип повреждения).
- **Автоматически маршрутизирует** обращения: уверенные случаи идут в обычную очередь, сомнительные — на ручную проверку.
- Даёт оператору **рабочее место** с очередью, карточкой обращения и возможностью исправить результат ML.
- Ведёт **журнал всех изменений** (audit log) и показывает клиенту понятную временную шкалу.

> [!IMPORTANT]
> Система **не принимает решений о страховой выплате** и использует **только вымышленные данные**. Реальные договоры, платёжные системы и АБС Т-Страхования не подключаются.

## 👥 Роли

| Роль | Что делает |
|---|---|
| **Клиент** | Создаёт и отправляет обращения, загружает файлы, видит статусы и временную шкалу, отвечает на запросы уточнений |
| **Оператор** | Работает с очередью, берёт обращения в работу, запрашивает материалы, исправляет ML-результат, завершает рассмотрение |
| **Администратор** | Всё то же, что оператор, плюс переназначение, смена приоритета, переоткрытие, метрики |
| **Система** | Автоматические переходы: проверки, постановка в очередь, ML-анализ, повторы, контроль сроков, уведомления |



## 🤖 ML-модуль и маршрутизация

Анализ выполняется **фоновой задачей** `ANALYZE_IMAGE`: загрузка файла не ждёт результата модели.

**Проверка качества фото**

| Проблема | Метрика | Порог «неприемлемо» |
|---|---|---|
| `BLURRY` | Laplacian variance | < 100 |
| `LOW_LIGHT` | Средняя яркость | < 40 |
| `OVEREXPOSED` | Средняя яркость | > 230 |
| `LOW_RESOLUTION` | min(ширина, высота) | < 480 px |
| `NO_DAMAGE_VISIBLE` | Площадь аномальных регионов | < 1% кадра |

**Классы повреждений:** `SCRATCH`, `DENT`, `BROKEN_GLASS`, `BUMPER_DAMAGE`, `HEADLIGHT_DAMAGE`

**Правила маршрутизации** (порог уверенности `threshold` настраивается, начальное значение **0.65**)

| Условие | Направление | Результат |
|---|---|---|
| Любое фото неприемлемого качества | `ADDITIONAL_DOCS` | Клиенту запрашиваются новые фото |
| Нет обязательного документа | `ADDITIONAL_DOCS` | Независимо от ML |
| Все фото OK, уверенность ≥ порога | `AUTO` | Результат принят, обращение идёт оператору |
| Все фото OK, уверенность < порога | `MANUAL_REVIEW` | Приоритет повышается до `HIGH` |

| Параметр | Значение |
|---|---|
| Одновременных пользователей | 10–20 |
| Обращений в минуту | 5–10 |
| p95 latency API (без ML) | < 500 мс |
| ML-анализ одного фото | < 5 с (фоновая задача) |
| Лимит файлов на обращение | 15 файлов, 100 MB суммарно |
